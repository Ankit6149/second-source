What problem this solves

The problem

Software outlives its documentation and sometimes its source. Rebuilding it by hand — or asking an AI to guess it — produces something that looks right and behaves wrong. Our own measurements: Muse rebuilding from scratch scored 1–2 of 6 on real behavior.

The idea

Don't guess. Observe the real system's behavior, write down only what was seen, let the AI reason about what remains unknown, then prove the rebuild matches by running the same cases against both.

Why it matters

Legacy migration, vendor lock-in, lost-source recovery, and auditing all need the same thing: a replacement you can verify, with evidence for every claim — not a confident demo.

Honest limits

Hosted execution is off

On the hosted backend you can sign in, create, authorize and track investigations; the execution step returns an explicit “disabled” rather than a simulated run. We refused to ship a mock labeled as real. The genuine engine runs locally today.

Muse hasn't beaten the notebook — yet

Where behavior was already observed, transcription wins. Muse's current tool surface (route contracts) can't express state/interpreter changes; its rejected edits are recorded, not hidden.

One divergence left

Vikunja's reference lists per-user default projects (Inbox) that the candidate does not seed. Documented, not papered over.

Future goals

1 · Muse in the loop, live

One orchestrated workflow — hypothesis → experiment selection → synthesis → verification → repair — running inside the product, with Muse proposing candidate code changes, not just route contracts.

2 · Hosted real execution

A secure worker that runs the engine for reachable targets, so the full journey completes on the website for any visitor, with the same honest labels.

3 · Spec → real source code

Generate ordinary, runnable source files from the behavioral specification, verified by the same evaluator — “AI builds the software,” with proof it matches.

4 · More surfaces

Deeper browser/UI reconstruction (DOM, layout, interaction state) beyond the current motion slice, each with its own independent fidelity measures.
