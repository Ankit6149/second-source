# Browser reconstruction slice (Workstream B)

A bounded, real browser experiment: infer a page's spring-back motion from
observed trajectories only, rebuild it from the inferred parameters, and test
the rebuild on a held-out interaction the fit never saw.

## Run

All commands run from this folder. Playwright + Chromium come from
`../product/node_modules` (`@playwright/test` 1.64.1, Chromium 1248) — nothing
is installed and no other part of the repo is modified.

```
node capture.mjs    # reference.html -> observations.json + screenshots
node fit.mjs        # observations.json (trajectory only) -> inferred.json + candidate.html
node evaluate.mjs   # held-out + adversarial comparison -> verdict.json (also prints it)
```

Pinned conditions: viewport 1280x800, deviceScaleFactor 1, headless Chromium.

| File | What it is |

| [capture.mjs](capture.mjs) | Loads the reference, records DOM summary, accessibility roles, layout boxes + computed styles for `#card` / `#hover-chip` / `#parallax-layer` / `h1` / `.stage`, hover + parallax probes, full/viewport screenshots, and a frame-indexed drag trajectory (+240px, sampled every `requestAnimationFrame`). | [fit.mjs](fit.mjs) | Infers motion parameters **from the trajectory in `observations.json` only** — it never opens `reference.html`. See "Method" below. Also generates `candidate.html` from the inferred values. |
| [candidate.html](candidate.html) | Independent implementation generated by `fit.mjs`; its `SPRING_K` / `SPRING_C` / `PARALLAX_FACTOR` literals are the inferred numbers, not hand-tuned. |

## Method (fit)

Post-release samples are modelled as a unit-mass damped spring
`x'' = -k*x - c*v` starting at the observed release position with `v = 0`.
A coarse grid (k 40-400, c 2-30) plus local refinement minimises trajectory
RMSE, with one extra fitted nuisance parameter: a time offset (0 / 16 / 32 /
48 ms) for the lag between the pointer-release timestamp and the first spring
update visible to the RAF sampler. A peak/log-decrement cross-check is
reported alongside. No hidden physics equations are claimed beyond this
explicit, stated model.

## Real results from the run in this folder

- Capture: 139 trajectory samples (110 post-release), overshoot to -57.41px
  after a +240px drag, final x = 0, observed parallax factor 0.35.
- Fit: **k = 188, c = 11.4** (wn = 13.71 rad/s, zeta = 0.416), fitted time
  offset 32 ms, **residual RMSE 1.54px** over 110 samples.
- Held-out evaluation (+140px): verdict **pass = true**
  - trajectory RMSE (candidate vs reference) **1.05px**
  - overshoot present in both (reference min -33.47px, candidate -32.60px)
  - settling time 0.646s vs 0.636s (diff 0.009s)
  - card layout max diff **0px** (tolerance 4px); parallax max diff **0px**
  - final state both "At rest", x = 0
- Adversarial controls (both correctly detected as different, threshold 8px):
  - no-overshoot variant (overdamped): RMSE 38.54px, overshoot absent
  - wrong-easing variant (linear return): RMSE 35.81px, overshoot absent

## What is proven

- Under the pinned viewport/browser above, the candidate — built only from
  trajectory-inferred parameters — reproduces the reference's held-out
  (+140px) spring-back trajectory to ~1px RMSE, with matching overshoot,
  settling time (within 10ms), final state, card geometry, and parallax.
- The evaluator is sensitive: deliberately wrong motion (overdamped
  no-overshoot, linear easing) is detected as different by a wide margin.

## What is NOT proven

- **Not** a recovery of the reference's exact source constants. The fit is an
  effective model (unit mass, semi-implicit integration, fitted time offset);
  k = 188 / c = 11.4 describe the observed motion, and no claim is made that
  these equal any constants inside `reference.html`.
- **Not** generalisation beyond this fixture: one card, one drag axis, one
  viewport, one browser (Chromium 1248), drag distances 140-240px.
- Hover easing is observed (computed styles recorded in `observations.json`)
  but not fitted or reconstructed as a trajectory; the candidate reuses the
  observed transition timing function.
- Parallax is verified only at scroll positions 0/200/400/600px and only as a
  linear factor; no scroll-linked behaviour beyond that is claimed.
- Frame timing is RAF-based (~60Hz samples with jitter); sub-frame physics
  and behaviour under dropped frames or other refresh rates are unverified.
- No claim about the wider product codebase — this slice is self-contained
  and touches nothing outside `browser-slice/`.
