# Product workspace: local acceptance

This branch contains the v0.8 workspace. The automated journey starts the real
local API and bounded NON_AI worker with **synthetic identities and fake private
Storage**. It blocks external browser requests and model transport. It does not
sign in to Google or establish hosted authentication, cloud persistence, or
live Meta inference. Test state is temporary and is deleted when the server stops.
The test-only server uses a 600-requests/minute ceiling because desktop and
mobile synthetic sessions share one pre-authentication rate bucket and the
Chromium acceptance needs to test cross-owner 404 denials without unrelated
429 throttling. The browser still injects an explicit 429, and backend
rate-limit regression tests remain active. Production defaults remain 60
requests/minute.

## Fresh checkout

Use Python 3.12 and Node 22 (the Node tests use experimental type stripping).
From the repository root, on Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[dev]"
cd product
npm ci
npx playwright install chromium
$env:PYTHON = (Resolve-Path ..\.venv\Scripts\python.exe).Path
npm test
npm run test:dom
npm run test:dom-integration
npm run test:browser
```

On Linux, create the same virtual environment with `python3 -m venv .venv`,
install with `.venv/bin/python -m pip install -e '.[dev]'`, and from `product`
set `export PYTHON="$(realpath ../.venv/bin/python)"`. Chromium may need system
libraries; the prepared CI workflow uses `npx playwright install --with-deps
chromium` on Linux. Dependency and browser installation require network access;
the acceptance journey itself does not access hosted services.

The real Chromium run exercises desktop, mobile emulation and keyboard paths,
local investigation and export, synthetic owner isolation, and selected failure
and recovery cases. It saves synthetic screenshots and an export in
`.runs/browser-acceptance/` at the repository root. These are not a recording,
nor are they proof of hosted acceptance. `npm run test:dom` and
`test:dom-integration` use a simulated DOM and are separate from Chromium.

For an interactive, local-only judge rehearsal after the setup above, run
`npm run demo:local` from `product`. It opens a Chromium window with a persistent
notice identifying its synthetic account and fake Storage. Choose either owned
fixture, review and authorize its scope, then queue and start a NON_AI run.
The browser blocks external requests and routes the test API to a loopback-only
server. Close the window to stop the launcher. The demo session and fake Storage
are temporary; do not use this launcher with real user data or credentials.
`npm run demo:local -- --smoke` runs a headless HTTP-fixture investigation and
verifies that the resulting NON_AI score is displayed.
`npm run demo:local -- --record` additionally records the same synthetic
journey and screenshots in `.runs/submission-video/`. Review the recording
before sharing; it does not demonstrate hosted login or live model inference.

## Check a downloaded export

From the repository root, after Python installation:

```powershell
.\.venv\Scripts\python scripts/verify_proof_bundle.py .runs/browser-acceptance/fixture-export.zip
```

Use `--sha256 <digest>` only when the digest was obtained independently. The
command bounds input, validates the bundle with the backend's verifier and does
not extract it. A successful check establishes integrity and internal
consistency, not provider attestation, a real model call, or correctness beyond
the recorded evaluator. It exits nonzero on an invalid or unreadable bundle.
